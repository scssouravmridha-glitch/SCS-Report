SCS JSON ব্যাকআপ — প্রথমে এই নির্দেশনা পড়ুন

স্ক্রিনশটের দুটি সমস্যা আলাদা:
১. ডেপ্লয় করা সাইটে পুরোনো কোড থাকলে আপনার scs-backup v2 JSON চিনবে না। এই প্যাকেজের সম্পূর্ণ নতুন ফাইল দিতে হবে।
২. Supabase-এ SQL ফাংশন না থাকলে scs_export_snapshot / schema cache ত্রুটি হবে। SQL চালানো ছাড়া শুধু GitHub-এ আপলোড করলে এটি ঠিক হবে না।

ধাপ ১ — Supabase সেটআপ (ডাটা মুছে না)
- Supabase Dashboard → আপনার ddgdjuxrpqpluzegzswj প্রজেক্ট → SQL Editor → New query খুলুন।
- এই প্যাকেজের supabase/backup-functions.sql ফাইলের পুরো কোড কপি করে সেখানে পেস্ট করুন। Run চাপুন। Success না হওয়া পর্যন্ত পরের ধাপে যাবেন না।
- পুরোনো প্যাকেজের SQL আগে চালানো থাকলেও এই আপডেটেড SQL পুরোটা আবার চালান। SQL ইনস্টল করতে Dashboard-এর অনুমতি দরকার।

ধাপ ২ — GitHub ও Netlify
- ZIP extract করে scs-live-update ফোল্ডারের ভেতরের সব ফাইল ও supabase ফোল্ডার GitHub repository-র root-এ আপলোড/প্রতিস্থাপন করে commit করুন। বিশেষ করে index.html, backup-tools.js এবং legacy-format.js—তিনটিই আপডেট করতে হবে।
- Netlify-তে নতুন commit-এর deploy সম্পন্ন হওয়ার পর সঠিক deploy-এর URL খুলুন এবং ব্রাউজারে Ctrl+Shift+R দিয়ে হার্ড রিফ্রেশ করুন। Build command খালি, Publish directory . রাখুন।
- Admin → 5. Logo, Control & Backup-এ গিয়ে 'ফরম্যাট আপডেট: আপনার scs-backup v2 JSON সমর্থিত' লেখা না দেখলে এখনো পুরোনো সাইট/কোড খোলা আছে।
- সেখানে 'Supabase সেটআপ পরীক্ষা' বাটন চাপুন। ব্যাকআপ ফাংশন পাওয়া গেছে দেখালে নিজের JSON এক্সপোর্ট করুন এবং নিরাপদ স্থানে রাখুন।

ধাপ ৩ — পুরোনো JSON রিস্টোর
- আগে বর্তমান ডাটার লাইফটাইম ব্যাকআপ নিন ও অন্য ডিভাইস বন্ধ রাখুন। Admin-এ JSON রিস্টোর থেকে পুরোনো JSON নির্বাচন করে নিশ্চিত করুন। রিস্টোরের পর পেজ রিফ্রেশ করে রিপোর্ট, অর্ডার, অ্যাটেনডেন্স ও সেটিংস পরীক্ষা করুন।
- ফাইলে যে মাস আছে তার রিপোর্ট ও অ্যাটেনডেন্স বদলাবে। একই অর্ডার আইডিতে ভিন্ন বিদ্যমান অর্ডার থাকলে নিরাপত্তার জন্য পুরো ইমপোর্ট বন্ধ হবে। অন্য মাস ও অর্ডার মোছা হয় না। ফাইলে ইতিহাস ও আসল লোগো/গানের binary না থাকলে তা ফেরানো যায় না।

ধাপ ৪ — Google Drive
- অ্যাপের ফোল্ডার ও সময় সেটিংস সেভ করুন। Google Apps Script-এ এই প্যাকেজের supabase/drive-backup.gs সম্পূর্ণ কোড পেস্ট করুন, Save করে setupHourlyBackup Run করুন এবং অনুমতি দিন। Executions ও Drive-এ টেস্ট ফাইল যাচাই করুন। পুরোনো script থাকলে এই নতুন script দিয়ে সম্পূর্ণ বদলে আবার setupHourlyBackup চালান।

নতুন এক্সপোর্টে পুরোনো JSON-এর মূল কাঠামোর সঙ্গে সম্পূর্ণ Supabase ব্যাকআপের জন্য scsSupabase অংশ যোগ করা হয়েছে। ব্যাকআপ ফাইল নিরাপদ স্থানে রাখুন। PIN বর্তমান খোলা Supabase RLS-এর বিরুদ্ধে সরাসরি API সুরক্ষা দেয় না।
